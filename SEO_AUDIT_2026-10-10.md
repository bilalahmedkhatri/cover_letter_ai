## Prioritized findings

### 1. High: public content and SEO signals depend on JavaScript

`index.html` contains an empty root and a noscript message. `index.tsx` uses client-side `createRoot`, while `App.tsx:169–198` adds titles, canonical links, and hreflang after rendering. The available public snapshot exhibits the same empty-content limitation. Google can render JavaScript, but crawlers and preview systems that do not render it receive very little useful content.

Prerender or server-render the public landing and informational pages with their content, titles, descriptions, canonical URLs, and language alternates in the initial HTML. The interactive generator can remain client-side. Verify both raw HTML and rendered HTML after deployment.

### 2. High: sitemap, canonicals, and internal links describe different URL sets

`public/sitemap.xml` lists `/`, `/dashboard`, `/about`, `/privacy`, and `/terms`. `App.tsx:175` canonicalizes pages to language-prefixed paths such as `/en` and `/en/about`. `Header.tsx:48–51` and landing-page CTAs still link to unprefixed paths. Unprefixed visits are normalized using browser history and browser/storage language, rather than an HTTP redirect.

Choose a stable URL policy. Generate the sitemap from canonical, indexable URLs, and make ordinary anchor hrefs use that same policy. If retaining unprefixed aliases, give them predictable HTTP redirects. Verify www/non-www consolidation separately: the code uses the non-www host, but the deployed host redirect was not observable.

All sitemap lastmod values are `2024-08-02`; verify them against actual content changes, update truthfully, or omit them. Do not replace them with the build date automatically.

### 3. High: arbitrary paths are configured to return the app shell

`vercel.json` rewrites almost every path to `index.html`. The client renders `NotFoundPage` for unrecognized routes, but this configuration does not provide a corresponding HTTP 404. `App.tsx` also assigns unknown pages the `/[locale]/404` canonical and emits language alternates for that error page.

Make unknown paths return an HTTP 404 at the hosting/server layer. Avoid advertising error pages through hreflang and indexing signals. Verify with an intentionally nonexistent URL after deployment. Current live status codes are unverified.

### 4. Medium: page-specific metadata is incomplete

The title changes in `App.tsx`, but the description, Open Graph fields, Twitter fields, and og:url stay at the static homepage values in `index.html`. About, privacy, terms, dashboard, and translated pages therefore inherit unrelated English homepage metadata. The static title targets cover letters, while the rendered English home title is the broader `AI Professional Letter Generator | Home` (`services/translations.ts:13`). The hero is similarly broad (`services/translations.ts:140`).

Create metadata for each indexable page and supported language. Use a clear home title and H1 around the actual product, for example “Free AI Cover Letter Generator”, if that free offer accurately describes the experience. Keep descriptions factual; remove unsupported guarantees about beating applicant tracking systems or securing interviews.

### 5. Medium: declared preview image is absent from this build

`index.html:23` and `:33` reference `/og-image.png`, but `public` contains only robots.txt and sitemap.xml. No such image is emitted by the current build. The broad rewrite may serve the HTML shell for the missing image path; that response was not verified live.

Add a real 1200 × 630 preview image, and check that its deployed URL returns an image content type and a successful status. Ensure asset URLs are handled as assets rather than rewritten to HTML.

### 6. Medium: initial JavaScript payload is large

Production build succeeded: the main JS chunk is 918.48 kB, or 251.60 kB gzip; CSS is 42.14 kB, or 7.44 kB gzip. Vite emitted its large-chunk warning. The dashboard and AI modules are imported into the same application path, making generator dependencies part of the initial bundle.

Lazy-load the dashboard and heavyweight AI/PDF functionality when needed. Measure mobile performance after deployment before making further optimizations. Bundle size is confirmed; poor LCP, INP, or CLS scores are not established by this audit.

### 7. Medium: hreflang advertises pages that are not fully translated

`App.tsx:185–198` emits all seven language alternatives for every page. `AboutUs.tsx` has an English body, and privacy/terms content is largely English even under translated routes. Language tags alone do not make these distinct translations.

Fully translate pages advertised as language alternatives, or limit the alternate set to meaningful translated versions. Preserve reciprocal alternates and self-canonicals on valid translations, with deterministic language URLs.

### 8. Medium: conversion events lack an analytics initializer in this checkout

`services/analyticsService.ts` sends events only when `window.gtag` exists. The reviewed app has no gtag loader or initialization. Form submission, generation, and PDF events are defined but may simply log a warning unless analytics is injected elsewhere in production. `CookieConsentBanner.tsx` records a preference without initializing or disabling an analytics integration.

Verify the production tracking setup. Connect the existing events to a consent-aware analytics implementation, then verify form submission, successful generation, and PDF download. Avoid sending resumes, personal details, or raw provider errors as analytics parameters.

## Additional app findings

- `vite.config.ts` injects Gemini environment values into browser code and `services/geminiService.ts:11` consumes them. If a real deployment key is configured, it is distributable in the client bundle. Put credentialed fallback requests behind a server endpoint with appropriate access and abuse controls. No key value was inspected or exposed in this audit.
- The current dashboard uses Puter first with Gemini fallback (`services/llms.tsx`), while About and Privacy describe Google/Gemini only. Update the product explanations to match the actual provider flow and browser-local saving behavior (`services/storageService.ts:80`).
- Privacy and Terms use the visitor's current date as “Last updated”; use a real revision date instead.
- Testimonials exist in translation strings, but their authenticity was not established. Retain only testimonials you can substantiate.
- The project currently has five public route types and a generic homepage. After technical fixes, consider distinct, useful pages for university admission letters, entry-level cover letters, and career-change cover letters. These are product-fit ideas, not Ahrefs-validated search opportunities. Validate demand and competing pages before investing in them; avoid duplicate pages that only change the keyword.
