## 1. Product ki haqeeqat aur pehli priorities

### 1.1 Hum abhi kya promote karenge?

**Positioning:** AILetterGen job applicants ko apni asli experience aur vacancy ki requirements se cover-letter draft tayyar karne mein madad deta hai. Applicant draft ko review aur edit karta hai.

Public marketing ka hero **job cover letter** hoga. Professional email, university application aur university research developer-only deferred features hain. Unke existing pages ya code ki maujoodgi public release ka saboot nahi. Inka launch, demo ya availability claim is campaign mein nahi karna.

| Kya keh sakte hain | Kis claim se bachna hai |
| --- | --- |
| Job-specific cover-letter draft banane mein madad | Guaranteed interview, guaranteed job, guaranteed acceptance |
| Apni experience aur vacancy ki details dein | Sirf vacancy URL se poori job automatically verify hoti hai |
| Draft ko review aur edit karein | AI ki har baat verified, native-perfect ya error-free hai |
| Paanch target languages mein writing ka demo, jab khud test ho | Har country ka recruitment format automatically certified hai |
| Copy/edit ka demo, jab live chal raha ho | ATS-approved ya ATS score guarantee |
| Availability aur limits ke liye current website dekhein | Free forever, unlimited free, no signup, jab tak live policy confirm na ho |

Current source mein PDF export image-based hai: text selectable/searchable nahi. Is liye PDF ko ATS-friendly keh kar promote nahi karna. Application portal ki instructions follow karwaein; zaroorat par reviewed text ko selectable-text document mein tayyar karna behtar hai.

### 1.2 Marketing se pehle jo cheezein clear honi chahiye

18 October ko local source inspect karne par:

- `/en`, `/ru`, `/pt`, `/fr`, `/es` language landing routes maujood hain.
- Blog article bodies abhi English hain. Localized blog navigation ka matlab translated article nahi.
- `/features`, `/guides`, `/compare`, `/pricing` ki primary translated content source mein English/Russian tak limited hai; doosri languages English canonical use karti hain.
- Local sitemap public canonical URLs se banti hai; local robots API ko disallow karta hai. Deployed sitemap ko alag verify karna zaroori hai.
- Analytics source mein mounted hai; actual production data collection verify nahi hui.
- `server/ai/providers.mjs` ka `node --check` syntax error deta hai; stray localhost text maujood hai. Is document mein repair nahi kiya gaya. **Local generation ki readiness blocked samjhein jab tak fix aur meaningful generation test na ho.** Is se production ka status automatically maloom nahi hota.
- Public web retrieval ne `/en` ka JavaScript shell dikhaya; robots/sitemap fetch tool se nahi khule. Yeh incomplete retrieval hai, website down ya Google rendering failure ka final proof nahi.

**Day 1 decision:** Live incognito browser mein signup → language select → fictional background + pasted vacancy → generation → edit/copy verify karein. Har promoted language ka short test karein. Agar flow fail ho to product CTA pause karein; isi calendar ki educational posts, keyword research aur assets par kaam jaari rakhein. Working demo record hone ke baad product promotion resume karein.

### 1.3 Priority ka order

1. Working product aur samajh aane wali language landing page.
2. Search Console/Yandex/Bing ki bunyaad aur measurement.
3. Useful job-application content aur real community conversations.
4. Images/videos se isi material ko reuse karna.
5. Relevant editors aur career creators se earned mentions.

Har jagah account kholna strategy nahi. Har activity ko sawal dein: **kya is se relevant applicant tak pohanch, useful feedback, ya first draft completion ka chance barhta hai?**

### 5.2 Multilingual SEO ki sab se zaroori baat

`/fr/blog/...` ka URL French lag sakta hai, lekin agar main article English hai to French audience ko translated article ka promise na karein. Existing English canonical behavior ko sirf indexing badhane ke liye override na karein.

Jab actual localized article publish karein:

- Body, headings, examples, intro aur CTA target language mein hon.
- Us language ka useful unique URL aur self-canonical ho.
- Equivalent translated pages ek doosre ko valid `hreflang` se reference karein; self-reference bhi ho.
- Sitemap mein sirf indexable canonical public pages; dashboard, account aur personal letters nahi.
- Country variants tab jab actual regional content ho. Brazil aur Portugal ke liye sirf do nearly identical thin pages na banayein.
- Internal links user ko usi language mein rakhein; English-only content par clear notice ho.

Google reference: [localized versions](https://developers.google.com/search/docs/specialty/international/localized-versions). Yeh future publishing checklist hai; is guide ne routes ya code implement nahi kiya.

### 5.4 Article ka practical brief

## 7. Content banane ka repeatable system

### 7.1 Ek idea ko assets mein badlein

**Ek weekly core topic → useful long post/article section → carousel → Pin → short video → community answer → editorial pitch.** Har asset apni jagah useful ho; sirf doosri jagah jaane ka teaser nahi.

| Week | Core theme | Applicant ka sawal | Product ka natural role |
| --- | --- | --- | --- |
| 1 | P1: vacancy se evidence | Mere paas kya relevant hai? | Brief ko draft mein organize karna |
| 2 | P2: generic vs specific + P3: first job | Experience kam ho to kya likhoon? | Supplied facts ko clear likhna |
| 3 | P4: career change + P5: review | Purana experience relevant kaise bane? | Draft edit aur final factual checks |
| 4 | P6: transparent demo/feedback | Tool actually mere kis kaam aata hai? | Working screen demo aur feedback |

### 7.2 Translation aur localization workflow

1. Master facts likhein: audience, problem, 3 useful points, genuine example, CTA.
2. Target-language draft banayein; Roman Urdu instructions public asset mein na jaane dein.
3. Names, job role, numbers, tone, accent marks aur Cyrillic manually inspect karein.
4. Back-translation se meaning compare karein; yeh native review ka substitute nahi.

### 16.3 Funnel aur metrics ko samajhna

| Stage | Sawal | Metric/evidence | Limitation |
| --- | --- | --- | --- |
| Visibility | Relevant logon ne dekha? | Search impressions, native post impressions | Impression user ya visit nahi |
| Interest | Kisi ne useful samjha? | Saves, substantive replies, profile visits | Likes alone intent nahi |
| Visit | Website par aaye? | Outbound clicks, analytics sessions | Native clicks sessions se different ho sakte hain |
| Signup | Account banaya? | Actually measured completed signup | Pageview ko signup nahi ginna |
| Activation | Pehla successful draft mila? | Verified success event/account aggregate | Current app mein attribution instrumentation confirm nahi |
| Return | Dobara use kiya? | Available privacy-respecting aggregate | Identity/session gaps aur small sample |
| Business value | Kya useful customer bana? | Consented feedback, actual paid conversion if any | No assumed revenue or conversion benchmark |

Signup/generation conversion chahiye to future instrumentation mein `signup_complete` aur `first_draft_success` jaise events useful ho sakte hain. **Yeh proposed event names hain; is task ne implement nahi kiye.** Letter text, CV text, email, prompts ya personal fields analytics ko na bhejein. Jab tak attribution available nahi, traffic source aur product usage ko alag report karein; unke beech exact causal claim na karein.

Basic formulas:

- Search CTR = clicks ÷ impressions × 100.
- Measured signup rate = attributed completed signups ÷ same-source eligible sessions × 100, **sirf jab dono reliably measured hon**.
- Helpful engagement per hour = meaningful replies/saves ÷ hours, reporting metric define karke.
- Activation rate = first-draft-success users ÷ relevant new users, same window/cohort mein, **sirf jab instrumentation ho**.

Zero denominator ya missing tracking ho to rate `N/A`. Apne test visits aur bot traffic jahan possible separate karein. Raw platform views ko same-definition metric ke baghair combine na karein.
